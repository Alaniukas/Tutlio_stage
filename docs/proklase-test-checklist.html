Before you start

Test DB ready The test organization “Paskutine Pamoka” already has all 7 PRO Klasė feature flags enabled in the test database, so you can test every flow as that org.

Run the app against the test DB:

npm run dev:test     # frontend (3000) + API (3002) pointed at TEST_SUPABASE_*

Flags & setup: Toggle org features in the Admin Panel (platform admin → organizations → features) or directly in organizations.features (JSONB). The relevant flags:

tutor_frequency_search trial_reservation_flow trial_followup_alert package_reservation_flow student_card_booking monthly_packages flexible_invitations

Tip — testing auto-release / expiry fast: the reserve→pay deadline defaults to 24h. To force a quick auto-release, either set a low deadline in the org features (trial_reservation_deadline_hours / package_payment_deadline_hours, in hours), or set the hold’s sessions.reservation_expires_at (and package lesson_packages.expires_at) to a past timestamp in the DB, then run the matching cron (see “Cron jobs”).
Local cron base URL: http://localhost:3002/api/<cron> — locally cron endpoints need no auth. On Vercel they require Authorization: Bearer <CRON_SECRET>.
Phase 1 Tutor Match · Trial Reservation · Follow-up Alert ▶

1. Tutor search by frequency tutor_frequency_search

  • As org admin of Paskutine Pamoka, open the “Find lesson / tutor” search (student card → find tutor).
  • Pick a subject, a free-time window, and a frequency (“Pamokų per savaitę”, e.g. 2×/week).
Expected: frequency-aware filtering + primary-tutor-first ordering, gated by the flag.

2. Trial reservation — reserve → pay → confirm trial_reservation_flow

  • Start a trial booking for a student; reserve a time slot.
  • Confirm the slot is held (not yet a confirmed lesson) with a payment deadline.
  • Complete payment within the deadline (Stripe test card or manual confirm).
Expected: reserve-then-pay holds the slot; confirmation + notifications happen only once, only after payment.

2b. Trial reservation — unpaid → auto-release trial_reservation_flow

  • Reserve a trial slot but do not pay.
  • Make it expire (low deadline, or set reservation_expires_at to the past).
  • Run the cron: GET http://localhost:3002/api/expire-trial-reservations.
Expected: unpaid holds auto-release after the deadline and the time becomes bookable again.

8. Trial follow-up alert (no package after trial) trial_followup_alert

  • Complete a trial lesson for a student (or run GET .../api/auto-complete-sessions after the end time).
  • Do not send a lesson package to that student.
  • Open the org admin dashboard and the student’s card.
Expected: post-trial students with no package are surfaced for follow-up; clears once a package is sent.
Phase 2 Package Pre-book · Card Booking · Monthly Packages · Flexible Invites ▶

3. Package pre-book (reserve times when sending a package) package_reservation_flow

  • On a student’s card, send/create a package; choose a tutor, price, and reserve lesson times up front.
  • Add several reserved times, then create the package.
Expected: a package can carry pre-booked, reserved slots that convert to lessons on payment.

4. Book lessons from the student card student_card_booking

  • Open a student card as org admin; use the embedded calendar / “Find & book lesson” to assign a tutor and book a lesson.
Expected: in-card booking works and always notifies the tutor.

5. Package payment deadline (24h before first lesson) package_reservation_flow

  • Pre-book a package with a first lesson some days out; note the generated payment deadline.
  • (Optional) set package_payment_deadline_hours in org features to change the window.
Expected: package payment window is anchored to the first lesson, configurable, with auto-release of unpaid holds.

6. Monthly packages (calendar-month validity + same-month reschedule) monthly_packages

  • Pay a package whose lessons fall in a given month; check the package expires_at.
  • As a tutor, try to reschedule a package lesson within the same month, then across into the next month.
Expected: package lessons are bound to their paid calendar month; reschedules stay in-month; moves are visible.

7. Flexible invitations (student and/or parent) flexible_invitations

  • Add a student and choose the invite target: only student, or student + parent (with parent contact details).
  • Open the parent registration link and complete it.
  • Schedule an upcoming lesson and run GET .../api/send-reminders.
Expected: invitations and reminders cover student and/or parent per the chosen target, without duplicates.
Cron jobs — how to trigger & schedules ▶

Locally (no auth needed), trigger any cron with a GET:

curl http://localhost:3002/api/expire-trial-reservations
curl http://localhost:3002/api/expire-packages
curl http://localhost:3002/api/send-reminders
curl http://localhost:3002/api/auto-complete-sessions

On Vercel they run on this schedule and require the bearer secret:

CronSchedulePurpose for this funnel
expire-trial-reservationsevery 15 minauto-release unpaid trial & package holds
expire-packagesevery 6 hoursdeactivate packages past their calendar month
send-remindersevery 5 minlesson reminders to student + parent(s)
auto-complete-sessionsevery 5 minmark finished lessons complete (drives the follow-up alert)
# Vercel / prod style
curl -H "Authorization: Bearer $CRON_SECRET" https://<host>/api/expire-trial-reservations
