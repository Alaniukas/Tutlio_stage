Tutlio Organic Reach Audit

What search engines and AI assistants actually received from the three Tutlio domains this week, what was repaired in code today, where organic traffic stands, and the order of work that will earn more of it for the 13 legacy and 23 new locales.

Production was returning HTTP 500 to crawlers on every money page. The fix is in the working tree and waits for a deploy.

Since roughly 1 September the crawler render of the home, pricing, about, contact, blog and tutor pages, plus all three sitemaps, failed on all domains. The same defect silently stopped the lesson-reminder cron, post-trial package emails, invoice generation and the auto-blog. Ten source files are corrected, a guard test now blocks a repeat, and 168 SEO tests plus both type checks pass.

Why it broke

Vercel runs each API file as a Node ES module and compiles the traced source files one by one, without bundling. Node then refuses a relative import that has no .js extension and cannot resolve the Vite @/ alias. Three modules added on 31 August and 1 September carried such imports, and an older alias chain through marketMoney.ts had the same flaw. One bad import anywhere in a function's import graph kills the whole function at cold start.

Why nothing caught it

Vitest, Vite and both tsc configurations resolve extension-less and alias imports, so every local check stayed green while production failed. The new test tests/api/esm-import-extensions.test.ts walks the runtime import graph of all 159 API functions and fails on the first offending specifier. It found the reminder and invoice chains that the SEO checks alone would have missed.

05 · The plan

Six moves, in the order they pay back

The sequence matters: nothing below the first item is visible to a search engine until the deploy lands, and items three and four only convert into traffic once the crawler sees a full page.

  1. Restore crawlability and keep it restored code donedeploy needed

    Deploy the import fixes, run the smoke script, resubmit the sitemaps and request indexing for the money pages. The guard test and the note in AGENTS.md stop the same class of bug from shipping again.

  2. Show crawlers the real landing page code done

    The bot render of the homepage now mirrors the human page: hero, old-way versus Tutlio comparison, calendar and portal sections, four pillars, seven linked feature cards, the four-step lesson-to-invoice walkthrough, the FAQ with links, and the closing offer with its trial chips. All 36 dictionaries already carried this copy, so every locale benefits at once.

    • Left out on purpose: the logo wall, case study and testimonials. The logo wall lists Wyzant, iTutor, HeyTutor, Learner and Fullmind under "trusted by". Unless those are real customers, remove it before AI engines repeat it; if they are, name them in the crawler page too.
    • Longer term, move the marketing routes to prerendered HTML so both audiences receive one document. The ops doc already flags dynamic rendering as a stopgap.

  3. Give the legacy locales something to rank content work

    • Turn the all-locale blog pipeline back on once the cron works. It already writes market-native briefs for all 13 locales; the eight locales with zero posts have never had a single run.
    • Expand the feature pages from 7 to the 12 hub features. Invoices, parent portal, messaging, whiteboard, white-label and statistics already have translated hub copy; each becomes a keyword page in 13 languages.
    • Native review of the two search strings per locale in src/lib/seoMeta.ts and of the hero, then per-market pages: comparisons against TutorBird, TutorCruncher, Teachworks and Oases, plus small tools such as an invoice template and a cancellation-policy template.

  4. Open the 23 new locales surface by surface decision needed

    • Marketing, pricing and feature pages already have translations and search titles for all 23. After native review, add a locale to SEO_LOCALES_BY_SURFACE.marketing; sitemap, hreflang and indexing follow automatically. Keep legal pages noindex until translated.
    • The blog needs a per-locale translations table; four more columns per language does not scale from 13 to 36.
    • Suggested first wave where the app is fully usable and tutoring demand is high: Italian, Brazilian Portuguese, Mexican Spanish, Turkish, Romanian and Czech.

  5. Generative engine optimisation partly done

    • Done: a Polish llms.txt and llms-full.txt for tutlio.pl, which used to serve the English text. Have a native speaker read it once.
    • Add sameAs links to the Organization schema once official LinkedIn, Facebook and directory profiles exist; none are recorded in the codebase today.
    • Get listed on G2, Capterra, GetApp, AlternativeTo and Product Hunt; answer engines cite those when asked for "tutoring management software".
    • Replace placeholder social proof with attributable customers and give the blog byline a real author page. Both feed E-E-A-T and AI citations.

  6. Measure the right thing partly done

    • Done in code: the traffic-sources query no longer counts Gmail and other Google apps as organic and folds ChatGPT's utm tags into the AI channel. It ships with the migration above.
    • Still open: Search Console and Bing Webmaster properties per domain, and storing the host next to the path in the pageview table so .lt, .pl and .com can be separated without guessing from the language.
